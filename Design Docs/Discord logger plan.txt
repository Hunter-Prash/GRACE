# Discord Logging for Memory Architecture

This plan outlines how we will push specific memory architecture logs (Indexer runs, RAG retrievals, deduplication drops) to a dedicated Discord channel.

## Why Discord over WhatsApp?
Discord is 100% free, renders code blocks and markdown perfectly, and provides a simple Webhook URL that requires zero authentication or SDKs. WhatsApp requires setting up Meta Developer APIs or paying for Twilio, which is overkill for logging.

## Open Questions
> [!IMPORTANT]
> Are you OK with using **Discord** for this? You will just need to create a free private Discord server, create a channel called `#grace-memory-logs`, and generate a Webhook URL.

## Proposed Changes

### 1. `backend/.env` (and `config.js`)
We will add an environment variable for the Discord Webhook URL.
- `DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...`

### 2. `backend/src/services/logger.service.js` [NEW]
We will create a lightweight logger utility that takes a string, prints it to the standard console, and concurrently fires an HTTP POST request to the Discord Webhook.

### 3. `backend/src/jobs/indexer.job.js` [MODIFY]
We will replace all `console.log("[Indexer] ...")` statements with our new Discord logger so you get push notifications every time the background job summarizes conversations, drops a duplicate, or upserts to Pinecone.

### 4. `backend/src/services/llm.service.js` [MODIFY]
We will replace the `console.log("[RAG ENGINE] ...")` statements so you get a ping whenever Grace pulls a memory from Pinecone to answer your question.
